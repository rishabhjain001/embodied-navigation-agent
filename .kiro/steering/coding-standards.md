# Project Coding Standards

These standards apply to every file in this codebase. Follow them before writing any code.

---

## Naming

**Functions and variables** should be descriptive but natural. Aim for the name a competent human would reach for first.

Good: `encode_frame`, `get_visual_features`, `parse_instruction`, `run_episode`  
Bad: `process_frame_and_extract_embedding_vector`, `execute_language_module_parsing_pipeline`

If a name needs more than three words, the function is probably doing too much.

**Files and folders** should follow conventions from real open-source RL and robotics projects (MiniGrid, Habitat-Lab, Stable-Baselines3). Use short, lowercase, underscore-separated names:  
`env.py`, `vision.py`, `language.py`, `policy.py`, `reward.py`, `train.py`, `api.py`, `dashboard.py`

No tool names, generator names, or AI assistant references anywhere in the codebase — not in files, comments, commit messages, or docstrings.

---

## Comments

Write comments to explain *why*, not *what*. If the code is clear, don't comment it.

```python
# clip expects normalized float32 in CHW format
frame = preprocess(frame).unsqueeze(0)
```

Not:
```python
# preprocess the frame and add batch dimension
frame = preprocess(frame).unsqueeze(0)
```

No auto-generated comment blocks. No section dividers like `# ===== SECTION =====`.

---

## Docstrings

Only add a docstring when the function's contract is genuinely non-obvious — inputs with unusual constraints, side effects, or tricky return semantics.

If a function is named well, skip the docstring. A three-line function named `encode_frame` does not need a docstring.

When you do write one, keep it short:

```python
def compute_similarity(frame_emb, text):
    """Returns cosine similarity in [-1, 1]. Raises ValueError on empty text."""
```

Not a multi-paragraph essay with Args/Returns/Raises sections for every parameter.

---

## Code style

- Simple and readable over clever
- No unnecessary abstractions or wrapper classes around single functions
- Flat is better than nested
- No TODO, FIXME, or HACK comments in MVP scope code
- No placeholder functions that just `pass` or `raise NotImplementedError` in MVP scope
- Prefer explicit over implicit — don't be clever with `*args/**kwargs` unless it's genuinely needed

---

## Git commit messages

Write like a human, not a changelog generator.

Good:
```
add reward shaping for collision penalty
fix session not resetting goal between episodes
wire up clip embeddings to ppo observation space
```

Bad:
```
feat(reward): implement collision penalty reward shaping module
refactor(env): reorganize environment initialization logic
fix(session): resolve issue with goal state persistence across episodes
```

Present tense, lowercase, no scope tags, no period at the end.

## .env.example

Include every required key, values blank, with a one-line comment explaining what each is for:

```
# Gemini Pro API key — get one at https://aistudio.google.com/
GEMINI_API_KEY=

# Path to the saved PPO model weights file
MODEL_PATH=models/policy.zip

# Grid world dimensions (rows x cols, minimum 8)
GRID_SIZE=10

# Maximum steps per episode before timeout
STEP_BUDGET=200

# Number of objects placed in the room per episode
OBJECT_COUNT=5

# Reward values (can tune without retraining from scratch)
REWARD_STEP_CLOSER=0.1
REWARD_STEP_AWAY=-0.1
REWARD_COLLISION=-0.5
REWARD_SUCCESS=10.0
REWARD_TIMEOUT=-5.0
```

## README

Write in neutral or first-person tone. No marketing language. No "this was generated by" attribution.

Must include:
- What the project does (one clear paragraph)
- Why it's interesting / what problem it demonstrates
- How to install and run it (exact commands)
- Architecture overview (ASCII diagram is fine)
- Known limitations and scope boundaries (MVP vs future phases)
- Citations for key dependencies: MiniGrid paper, CLIP paper, PPO paper

Example opening — not this:
> "This cutting-edge AI agent leverages state-of-the-art vision-language models to achieve unprecedented navigation performance!"

Write this instead:
> "An embodied navigation agent that follows natural language instructions in a simulated grid environment. It combines CLIP for visual perception, Gemini for instruction parsing, and a PPO policy trained with Stable-Baselines3."
